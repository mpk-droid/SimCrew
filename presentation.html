SimCrew

Automated Developer Experience Testing

Muthukumaran PK · Tooling Experience · July 2026

Why?

We don't have confidence about the
Developer Experience

  • We ship repos — starter kits, templates, tools
  • We have no way to know how easy it is for developers to use them
    • Is the onboarding seamless? Are there gaps in docs? Are there hurdles?
  • As it is today, the only way we find issues is when customers complain
  • We want to find out before they do

SimCrew

Give it a git repo URL. It spins up AI personas that independently clone the repo and evaluate it like real developers.

Should we integrate this into
Workflow Validation?

What would integration look like?

Today (separate)

SimCrew

  • Standalone app with own UI & DB
  • Own orchestrator, own agent containers
  • Own persona & journey definitions
  • Tests repos via terminal (CLI tools)

Workflow Validation

  • Director orchestrates Performers
  • Performer controls browser via Playwright
  • Tests running RHOAI product via UI
  • CI pipeline, dashboard, insights pipeline

No connection between the two

After Integration

  • Our engine becomes a CLI Performer plugin in the Director
  • Director sends: persona + journey + repo URL
  • We send back: findings + score
  • Shared persona & journey spec format
  • DX findings feed into Customer Insights
  • Scores show up in Workflow Validation Dashboard
  • Same CI pipeline — nightly runs, JUnit XML

Pros & Cons of Integrating

Pros

  • One team, one framework, one dashboard
  • Shared CI infrastructure & cluster lifecycle
  • Customer Insights feeds both test types
  • Broader coverage — product + developer experience
  • No duplicated effort on personas, journeys, reporting

Cons

  • Different stacks (TypeScript vs Python) — integration cost
  • Different test targets (browser vs CLI) may not share much code
  • Risk of slowing both teams while integrating
  • SimCrew is early — may need to mature before merging

Questions & Next Steps

  • Should we wait until SimCrew gains more traction and maturity before integrating?
  • Would it make sense to have customer workflow testing and developer experience testing under one repo?
  • What's the right level of integration to start with?
